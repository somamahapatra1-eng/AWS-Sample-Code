AKS: Azure Kubernetes Service

What It Does

AKS is Azure's managed Kubernetes service. You provide container images, Kubernetes manifests (or Helm charts), and AKS runs them across a cluster of VMs. Kubernetes orchestrates scheduling, networking, storage, and scaling.

Unlike Azure Functions (serverless), AKS gives you full control: custom runtimes, long-running processes, GPU workloads, stateful services.

Key Concepts

  • Cluster — A set of VMs running Kubernetes. AKS manages the control plane.
  • Node Pool — A group of VMs with the same specs. Run system pods on one pool, app pods on another.
  • Pod — The smallest unit. One or more containers. Usually one container per pod.
  • Deployment — Desired state. "Run 3 replicas of this image, keep them running, roll out updates."
  • Service — Load balancing. Expose pods inside the cluster or to the internet.

Terraform: AKS Cluster

provider "azurerm" {
  features {}
}

resource "azurerm_resource_group" "main" {
  name     = "rg-aks-prod"
  location = "East US"
}

resource "azurerm_kubernetes_cluster" "main" {
  name                = "aks-prod-cluster"
  location            = azurerm_resource_group.main.location
  resource_group_name = azurerm_resource_group.main.name
  dns_prefix          = "aks-prod"
  kubernetes_version  = "1.27"

  default_node_pool {
    name       = "default"
    node_count = 3
    vm_size    = "Standard_D2s_v3"

    upgrade_settings {
      max_surge = 1
    }
  }

  identity {
    type = "SystemAssigned"
  }

  network_profile {
    network_plugin = "kubenet"
    service_cidr   = "10.0.0.0/16"
    dns_service_ip = "10.0.0.10"
  }

  depends_on = [
    azurerm_resource_group.main
  ]
}

# Output kubeconfig
output "kube_config" {
  value     = azurerm_kubernetes_cluster.main.kube_config_raw
  sensitive = true
}

Deploy an App with Terraform + Helm

Helm is the package manager for Kubernetes. Instead of writing YAML for every resource, you use a Helm chart (pre-written templates with values). 

provider "helm" {
  kubernetes {
    host                   = azurerm_kubernetes_cluster.main.kube_config.0.host
    client_certificate     = base64decode(azurerm_kubernetes_cluster.main.kube_config.0.client_certificate)
    client_key             = base64decode(azurerm_kubernetes_cluster.main.kube_config.0.client_key)
    cluster_ca_certificate = base64decode(azurerm_kubernetes_cluster.main.kube_config.0.cluster_ca_certificate)
  }
}

resource "helm_release" "api_app" {
  name             = "api-app"
  repository       = "https://example.com/charts"
  chart            = "api-app"
  namespace        = "default"
  create_namespace = true

  values = [
    yamlencode({
      image = {
        repository = "example.azurecr.io/api-app"
        tag        = var.app_version
      }
      replicaCount = 3
      resources = {
        requests = {
          cpu    = "100m"
          memory = "256Mi"
        }
        limits = {
          cpu    = "500m"
          memory = "512Mi"
        }
      }
      autoscaling = {
        enabled     = true
        minReplicas = 3
        maxReplicas = 10
        targetCPUUtilizationPercentage = 70
      }
    })
  ]
}

Direct Kubernetes YAML

Or deploy Kubernetes manifests directly with Terraform: 

resource "kubernetes_deployment" "api_app" {
  metadata {
    name = "api-app"
  }

  spec {
    replicas = 3

    selector {
      match_labels = {
        app = "api-app"
      }
    }

    template {
      metadata {
        labels = {
          app = "api-app"
        }
      }

      spec {
        container {
          name  = "api-app"
          image = "example.azurecr.io/api-app:latest"
          port {
            container_port = 8080
          }

          resources {
            requests = {
              cpu    = "100m"
              memory = "256Mi"
            }
            limits = {
              cpu    = "500m"
              memory = "512Mi"
            }
          }

          env {
            name  = "ENVIRONMENT"
            value = "production"
          }
          env {
            name = "CONNECTION_STRING"
            value_from {
              secret_key_ref {
                name = "app-secrets"
                key  = "connection_string"
              }
            }
          }
        }
      }
    }
  }
}

resource "kubernetes_service" "api_app" {
  metadata {
    name = "api-app-service"
  }

  spec {
    selector = {
      app = "api-app"
    }

    port {
      port        = 80
      target_port = 8080
    }

    type = "LoadBalancer"
  }
}

AKS with App Insights

Link the cluster to App Insights for pod monitoring: 

resource "azurerm_kubernetes_cluster" "main" {
  # ... other config ...

  oms_agent {
    enabled                    = true
    log_analytics_workspace_id = azurerm_log_analytics_workspace.main.id
  }

  monitor_metrics {
    enabled = true
  }
}

Multi-Region AKS

Deploy the same app to multiple clusters (regions) for high availability: 

variable "regions" {
  default = ["East US", "West Europe"]
}

resource "azurerm_kubernetes_cluster" "main" {
  for_each = toset(var.regions)

  name                = "aks-${lower(replace(each.value, " ", "-"))}"
  location            = each.value
  # ... rest of config ...
}

AKS vs Azure Functions: When to Use

Factor Azure Functions AKS
Execution time Max 10 min (consumption) Unlimited
Cold start 10–30 sec (consumption) None (always-on)
Cost at low volume $0.20/1M invocations VMs cost $100+/month
Scaling Automatic (to limits) Automatic with HPA
Use case Event handlers, webhooks Always-on APIs, batch jobs, stateful apps
Node pools: You can have multiple node pools in one cluster. For example, a system pool for kube-dns and ingress, and a workload pool for your apps. Use node affinity to schedule pods on specific pools.

Common Patterns

  • API server — Deployment with 3+ replicas, LoadBalancer service, autoscaling on CPU
  • Background job — CronJob or Job resource, runs once on schedule
  • Stateful service — StatefulSet for databases, message queues (better do this outside AKS)
  • Ingress controller — One ingress-nginx per cluster, routes HTTP/HTTPS to services
