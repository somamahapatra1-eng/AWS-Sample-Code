Azure Function App: Serverless Compute

What It Does

Azure Functions is Azure's serverless compute service. You write a function (like a Python script or Node.js handler), deploy it, and Azure runs it on-demand. You pay only for execution time.

Functions are organized in a Function App. One Function App contains multiple functions, a storage account, and runtime settings.

Key Concepts

  • Triggers — What invokes the function: HTTP request, timer, message queue, blob storage event
  • Bindings — Inputs and outputs. A function reads from Table Storage, writes to Cosmos DB
  • Host — The runtime environment. Managed by Azure (no server provisioning)
  • Storage Account — Stores function code, blobs, and queues

Dynamic tier (Y1): Consumption plan. You pay per execution. Cold starts are slower but cost-effective.
App Service Plan: Premium tier for predictable traffic and faster cold starts.

HTTP-Triggered Function in Python

import azure.functions as func

def main(req: func.HttpRequest) -> func.HttpResponse:
    tenant_id = req.get_json().get("tenantId")
    
    if not tenant_id:
        return func.HttpResponse(
            '{"error": "tenantId required"}',
            status_code=400,
            mimetype="application/json"
        )
    
    return func.HttpResponse(
        f'{{"accepted": true, "tenant": "{tenant_id}"}}',
        status_code=202,
        mimetype="application/json"
    )

When to Use

Azure Functions is best for:

  • Event-driven workloads (queue messages, blob uploads, timers)
  • Lightweight services (under 15 minutes execution time)
  • Cost-sensitive deployments (pay only for invocations)
  • Rapid prototyping and integrations

Avoid for:

  • Long-running jobs (max 10 minute timeout on consumption plan)
  • Always-on services (use App Service or AKS instead)
  • Heavy background processing (use Azure Batch or Spark)

Cold Starts

On a consumption plan, the first invocation may take 10–30 seconds (cold start) because Azure is provisioning a runtime. Subsequent calls (within a few minutes) reuse that runtime. For predictable latency, use a Premium plan with reserved capacity.
