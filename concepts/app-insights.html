Application Insights: Monitoring & Observability

What It Does

Application Insights is Azure's observability service. Your application sends telemetry (logs, metrics, traces, exceptions) to App Insights, and you query it to understand what the app is doing and why it failed.

It works with Functions, App Service, AKS, and any app that imports the SDK and sends events.

Three Pillars of Observability

  • Metrics — Numbers over time. Request count, latency, CPU, memory. Aggregate only.
  • Logs — Individual events. Every request, error, custom message. Store the full context.
  • Traces — Distributed traces. Follow one request across multiple services. See timing at each hop.

Terraform: Create App Insights

resource "azurerm_application_insights" "main" {
  name                = "appinsights-prod"
  location            = azurerm_resource_group.main.location
  resource_group_name = azurerm_resource_group.main.name
  application_type    = "web"
  retention_in_days   = 30
}

# Link to Function App
resource "azurerm_function_app" "main" {
  # ... other config ...

  app_settings = {
    APPINSIGHTS_INSTRUMENTATIONKEY = azurerm_application_insights.main.instrumentation_key
    APPLICATIONINSIGHTS_CONNECTION_STRING = azurerm_application_insights.main.connection_string
  }
}

Send Custom Events from Python

from opencensus.ext.azure.log_exporter import AzureLogHandler
import logging

# Configure logging
logger = logging.getLogger(__name__)
logger.addHandler(AzureLogHandler())
logger.setLevel(logging.INFO)

def main(req):
    tenant_id = req.get_json().get("tenantId")
    
    # Log custom event
    logger.info(f"Processing tenant {tenant_id}", extra={
        "custom_dimensions": {
            "tenant_id": tenant_id,
            "user": req.headers.get("X-User-ID"),
            "timestamp": datetime.now().isoformat()
        }
    })
    
    try:
        result = process_tenant(tenant_id)
    except Exception as e:
        logger.exception(f"Failed to process tenant {tenant_id}")
        raise
    
    return func.HttpResponse(json.dumps(result), status_code=200)

Query Logs with KQL

Use Kusto Query Language (KQL) to search App Insights. In the Azure portal, open App Insights → Logs and run queries. 

// Find slow requests
requests
| where duration > 5000
| summarize count() by bin(timestamp, 1m), name
| render timechart

// Exceptions in the last hour
exceptions
| where timestamp > ago(1h)
| project timestamp, problem_id, detail = tostring(details.["Exception Info"].Value)

Alerts

Set up alerts so you're notified when something breaks. 

resource "azurerm_monitor_metric_alert" "high_latency" {
  name                = "alert-high-latency"
  resource_group_name = azurerm_resource_group.main.name
  scopes              = [azurerm_application_insights.main.id]
  description         = "Alert when response time > 5s"
  severity            = 2
  enabled             = true
  frequency           = "PT1M"
  window_size         = "PT5M"

  criteria {
    metric_name      = "requests/duration"
    metric_namespace = "microsoft.insights/components"
    aggregation      = "Average"
    operator         = "GreaterThan"
    threshold        = 5000 # milliseconds
  }

  action {
    action_group_id = azurerm_monitor_action_group.main.id
  }
}

Distributed Tracing

If a Function calls another Function or an API, set the correlation ID so you can follow the full request path. 

from opencensus.trace.tracer import Tracer
from opencensus.ext.azure.trace_exporter import AzureExporter

tracer = Tracer(exporter=AzureExporter(connection_string=connection_string))

def main(req):
    with tracer.span(name="process_tenant") as span:
        span.add_attribute("tenant_id", tenant_id)
        
        # Call another service
        response = call_downstream_api(tenant_id)
        
        span.add_attribute("downstream_status", response.status_code)
    
    return func.HttpResponse("OK")
Retention: By default, App Insights keeps logs for 30 days. Pay extra for longer retention.
Sampling: On high volume, App Insights samples (e.g., 10% of events) to control cost.

When to Use

Use App Insights if:

  • You need observability for Azure services (Functions, App Service, AKS)
  • You want a managed solution (no self-hosted infrastructure)
  • You need KQL queries and dashboards in the Azure portal

Consider alternatives if:

  • Your apps are not on Azure (use Datadog, New Relic, Honeycomb)
  • You prefer open standards (use Prometheus + Grafana, or OpenTelemetry)
  • Cost is critical at high volume (self-hosted ELK stack)
