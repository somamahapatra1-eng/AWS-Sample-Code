DevOps: 100 interview questions

Thirty-four beginner questions, thirty-three intermediate, and thirty-three advanced. Each one has a direct answer.

Beginner

1. What is DevOps?

A way of working where the people who build a system also run it, with automation between a change and production. It is not a job title and not a tool.

2. What is the goal?

Smaller changes, shipped more often, with a short path to repair when they fail. Speed without a repair path is just risk.

3. What is CI?

Continuous integration. Every change is built and tested with the main line, soon after it is pushed, so conflicts show up in hours, not months.

4. What is CD?

Continuous delivery means the main line is always in a state you could release. Continuous deployment means it actually releases without a manual gate.

5. What is a pipeline?

The automated steps from commit to a running system: build, test, scan, package, deploy. A human clicking those steps is not a pipeline.

6. What is a build artifact?

The output you deploy, such as an image or a package, identified by a version. Rebuild from source in production is how you get a different binary than you tested.

7. What is build once, deploy many?

The same artifact moves from test to production. Configuration changes. The binary does not. Rebuilding per environment hides drift.

8. What is a environment?

A place the artifact runs: dev, test, production. They should differ by config and scale, not by a different build.

9. What is a promotion?

The same digest is allowed into the next environment after checks pass. Promotion is not a new build with a new tag.

10. What is trunk-based development?

Short-lived branches merged to one main line often. Long branches diverge and the merge becomes a project.

11. What is Git Flow?

A branching model with long-lived develop and release branches. It fits slow releases. It fights continuous delivery.

12. What is a feature flag?

A switch that turns behavior on without a deploy. It separates shipping code from exposing it. Flags that nobody removes become a second codebase.

13. What is a dark launch?

The code runs in production and the user does not see it. You watch errors, then turn the flag on.

14. What is a canary release?

A small share of traffic gets the new version. You compare errors and latency, then increase the share or stop.

15. What is blue-green?

Two full environments. You switch traffic. Rollback is a switch back. You pay for both while they overlap.

16. What is a rolling deploy?

Instances update a few at a time. It needs spare capacity and a health check. A bad health check rolls a failure to every instance.

17. What is a rollback?

Return to the previous artifact. It is fast when the artifact is immutable. It does not undo a data migration that already ran.

18. What is a database migration risk?

The new code and the old code may both be live during a roll. Migrations must work with both, or you stop the world.

19. What is expand and contract?

Add the new schema, ship code that uses both, backfill, then remove the old schema. It is how you migrate without a long outage.

20. What is infrastructure as code?

The servers, networks, and policies are files in version control. A change is a review, not a click that nobody can repeat.

21. What is immutable infrastructure?

You replace a machine instead of patching it in place. The new one comes from the same recipe. Snowflakes cannot be rebuilt.

22. What is configuration drift?

The running system no longer matches the recipe. Someone fixed it by hand. The next apply either overwrites the fix or is too scared to run.

23. What is GitOps?

A controller in the environment pulls the desired state from Git. You do not give a pipeline broad credentials to push. Drift is corrected or alerted.

24. What is a pull versus push deploy?

Push means CI logs in and changes the cluster. Pull means the cluster fetches Git. Pull keeps credentials inside the environment.

25. What is a secret in a pipeline?

A short-lived credential injected at runtime, not stored in the repository. The log must mask it. A secret printed once is burned.

26. What is least privilege for CI?

The job that builds should not be the job that deploys to production. Split them. A compromised test job should not own production.

27. What is a protected branch?

Main cannot be pushed to directly. Changes arrive by review. The protection is the control, not the convention.

28. What is a required check?

The merge waits for the pipeline. A green button that can be skipped is not a control.

29. What is a flaky test?

A test that fails and then passes with no change. It trains people to ignore red builds. Quarantine it and fix it. Do not rerun until green and move on.

30. What is a test pyramid?

Many fast unit tests, fewer integration tests, a few end-to-end tests. Inverting it makes the pipeline slow and brittle.

31. What is shift left?

Find the problem earlier: in the editor, the pull request, or CI, not in production. It does not mean skipping production observability.

32. What is a code review?

A second person reads the change for behavior, risk, and operability. A review that only checks style is a linter you have not installed.

33. What is a definition of done?

The change is merged, deployed, observed, and the flag or the migration plan is written down. Merged alone is not done.

34. What is DORA?

Four measures: deploy frequency, lead time, change failure rate, and time to restore. They describe the system, not a person's worth.

Intermediate

35. What is lead time?

From commit to running in production. A long lead time is usually waiting, not compiling.

36. What is change failure rate?

The share of deploys that cause a restore, a hotfix, or an incident. A team that never fails and never ships is not winning.

37. What is time to restore?

How long until users are fine again. A fast rollback beats a long debugging session with the bad version still live.

38. What is an error budget?

The allowed unreliability from the SLO. When it is gone, you spend time on reliability instead of features. It is a policy, not a graph.

39. What is an SLO?

A target, such as 99.9 percent of requests under 300 milliseconds. It is internal. An SLA is a promise to a customer with consequences.

40. What is an SLI?

The measurement behind the SLO, such as the share of successful checks. A bad SLI makes a pretty SLO that does not match user pain.

41. What is toil?

Manual, repetitive work that scales with the system. Automate the kind you do every week. Do not automate a one-off you do not understand.

42. What is an on-call rotation?

A named person who responds, with a backup, a schedule, and a limit on how often they are up at night. Hero culture is not a rotation.

43. What is a runbook?

Steps for a known alert. It should say how to confirm, how to mitigate, and when to escalate. A runbook that is wrong is worse than none if people follow it blindly.

44. What is a blameless postmortem?

A write-up of what the system allowed, not who to punish. Action items change the system. A lecture does not.

45. What is an incident commander?

One person who coordinates. They do not have to be the deepest expert. Experts debug. The commander keeps a timeline and decides.

46. What is severity?

A shared scale for impact. Sev-1 is users widely affected. Arguing the number during the incident wastes time. Set the scale before you need it.

47. What is a status page?

A place users can see that you know. Update it even when the update is that you are still looking. Silence reads as indifference.

48. What is observability?

You can ask a new question about the system from its logs, metrics, and traces. A dashboard of CPU is monitoring. It is not enough.

49. What are the golden signals?

Latency, traffic, errors, and saturation. If you alert on one thing, start here, not on a metric that looks interesting and means nothing.

50. What is an alert worth paging?

A symptom a human must act on now. High CPU with a healthy user experience is a ticket, not a page.

51. What is alert fatigue?

Too many pages, so the real one is missed. Delete alerts that nobody acted on. Every page needs an owner and a next step.

52. What is a tracing span?

One timed piece of a request as it crosses services. A trace shows where the time went. Logs show what one service thought.

53. What is correlation id?

An id passed through every hop so logs from one request can be found together. Without it, five services look like five incidents.

54. What is a health check?

A cheap request that means the process can serve. A check that calls every dependency turns a small outage into a total one.

55. What is a readiness check versus a liveness check?

Readiness removes the instance from traffic. Liveness restarts it. Restarting a process because a database is down makes the database's day worse.

56. What is capacity planning?

You know how much headroom you have before a launch. Autoscaling is not a substitute for a limit you have never tested.

57. What is a load test?

Traffic that looks like production, against a system you can break. Testing in production without a plan is not a load test. It is an incident.

58. What is a game day?

A scheduled failure: kill a zone, expire a certificate, or revoke a credential. You learn whether the runbook works while nobody is angry.

59. What is chaos engineering?

A deliberate fault to test a hypothesis, such as the system stays up if one node dies. Random breakage with no hypothesis is just noise.

60. What is a staging environment that lies?

It is smaller, has different data, and skips the real identity provider. A pass there does not mean production will pass. Say what it does not prove.

61. What is production-like?

The same architecture, the same versions, and a realistic scale for the risk you care about. A laptop is not production-like for a network outage.

62. What is a change window?

A time when a risky change is allowed, with people awake. It is not a reason to batch a month of changes into one terrifying night.

63. What is a deployment freeze?

A period, such as a known peak, when you do not change production. Incidents still get fixes. Features wait.

64. What is progressive delivery?

Canaries, flags, and measured rollout instead of a big bang. The tool is less important than the ability to stop halfway.

65. What is a platform team?

A group that builds the paved road: pipelines, clusters, and templates. Product teams should not each invent a deploy system.

66. What is a golden path?

The supported way to ship. It is easy on purpose. The unsupported path exists and is slower, so people choose the path you can operate.

67. What is developer experience?

How long from a new laptop to a deployed change. A painful path produces shadow pipelines you do not control.

Advanced

68. What is shadow IT in a pipeline?

A script on a laptop that deploys because the official path is too slow. The fix is a faster official path, plus removing the credentials from the laptop.

69. What is SBOM?

A list of components in the artifact. When a library is compromised, you can say whether you shipped it.

70. What is vulnerability management?

A loop: scan, decide, patch, or accept with a date. An unscanned image and a forever-accepted finding are the same risk.

71. What is a waiver?

A written decision to ship a known issue, with an owner and an expiry. A waiver with no expiry is a quiet acceptance.

72. What is supply chain security?

You know where the artifact came from, who signed it, and which dependencies it used. A pulled latest tag has none of that.

73. What is signing a build?

The pipeline attests the digest. The environment rejects unsigned images. Signing after the fact on a laptop does not prove the pipeline built it.

74. What is environment parity?

Tools and versions match. Data and scale may not. Pretending they match is how a test that cannot fail gets trusted.

75. What is a config versus a secret?

Config can be in Git. A secret cannot. If rotating it would matter, it is a secret.

76. What is a twelve-factor app?

A set of habits: one codebase, config in the environment, stateless processes, logs on stdout. It is a checklist, not a framework.

77. What is stdout logging?

The process writes logs to standard output. The platform collects them. A log file inside the container disappears with the container.

78. What is an artifact repository?

The store of build outputs. Production pulls from it. A rebuild from a laptop is not the repository.

79. What is semantic versioning?

A version that says whether a change breaks callers. It only works if people mean it. A calendar version is fine if you do not promise compatibility.

80. What is a changelog?

What changed for the operator, not a dump of commit subjects. Say what to do if they upgrade.

81. What is backward compatibility?

Old clients keep working. Breaking it needs a new version and a date when the old one stops.

82. What is an API deprecation?

A announced end. Ship the replacement, measure who still calls the old one, then remove it. Removing it on the day you announce it is an incident.

83. What is a post-deploy check?

An automated look at the error rate after the roll. If it rises, stop or roll back without waiting for a human to notice.

84. What is a manual approval?

A gate before production. Use it for a risky change. A gate on every change that nobody reads is delay, not safety.

85. What is separation of duties?

The author does not approve their own production change. In a small team, a second person on the pull request is the practical form.

86. What is bus factor?

How many people can operate the system. One is a risk. Write the runbook and share the on-call before that person is on holiday.

87. What is documentation that rots?

A wiki nobody updates. Put the steps next to the code or generate them. A wrong runbook is an attractive nuisance.

88. What is an SLO review?

A regular look at whether the target still matches the user, and whether the error budget was spent on the right work.

89. What is ticket-driven ops?

Every change has a record. Useful for audit. Useless if the ticket says 'deploy stuff' and the detail is in a chat that expires.

90. What is chatops?

Commands from chat that a bot runs, with the same logs as CI. A human pasting a production command into chat is not chatops.

91. What is infrastructure drift detection?

A scheduled plan that shows what would change. Someone looks at it. A plan that nobody reads is a log line.

92. What is a break-glass account?

An emergency path with strong identity, short use, and an alert when it is used. A shared root password in a vault note is not break-glass. It is a standing risk.

93. What is least privilege over time?

Access expires. A standing admin grant from a project two years ago is how old laptops still own production.

94. What is a production readiness review?

A short list before a new service is on call: owner, dashboard, alert, rollback, and capacity. A service without an owner is a future incident.

95. What is you build it, you run it?

The team that ships the service holds the pager. A separate ops team that learns about the change at 2 a.m. cannot be your only safety net.

96. What is a platform SLO?

The cluster or the pipeline has its own target. If the platform is down, every product SLO is a lie. Measure the platform too.

97. What is a deploy metric you should not game?

Deploy count, if people split empty commits to look fast. Pair frequency with failure rate and time to restore.

98. What is a good pipeline's first failure?

Fast and close to the change: lint and unit tests in minutes. A two-hour suite that fails on a typo will be bypassed.

99. How do you start DevOps on a team that only has tickets?

Put the build in one script everyone runs, then run that script in CI, then stop deploying any other way. Culture follows the path that is easier.

100. What is a pipeline you can rerun?

The same commit produces the same artifact. A pipeline that depends on a laptop file or a moving latest tag cannot be rerun when production breaks.
