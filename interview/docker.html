Docker: 100 interview questions

Thirty-four beginner questions, thirty-three intermediate, and thirty-three advanced. Each one has a direct answer.

Beginner

1. What is a container?

A process with its own filesystem, network, and limits, running on a shared kernel. It is not a virtual machine.

2. What is an image?

A read-only template made of layers. A container is a running instance of an image plus a writable layer.

3. What is a Dockerfile?

The recipe that builds an image: base image, files copied in, and the command to run.

4. What is a layer?

One instruction's result, cached and reused. Changing an early instruction rebuilds every layer after it.

5. What is a base image?

The FROM image. A small, maintained base reduces vulnerabilities and download time.

6. What is a tag?

A name pointing at an image. latest is only a tag. It moves. Pin a version or a digest.

7. What is a digest?

A hash of the image content. Pinning the digest means the build cannot silently change.

8. What is docker build?

It runs the Dockerfile and produces an image. The context is the set of files sent to the daemon. A huge context is slow.

9. What is .dockerignore?

Files left out of the build context. Use it for .git, node_modules, and secrets so they are not sent or copied.

10. What is COPY versus ADD?

COPY puts files in the image. ADD also unpacks archives and can fetch URLs. Prefer COPY unless you need that extra behavior.

11. What is CMD?

The default command. A docker run argument replaces it.

12. What is ENTRYPOINT?

The executable that always runs. CMD becomes its arguments. Use ENTRYPOINT for a fixed binary and CMD for default flags.

13. What is WORKDIR?

The directory later instructions and the process use. It creates the directory if needed.

14. What is ENV?

An environment variable baked into the image. Do not put secrets in ENV. They stay in the image history.

15. What is ARG?

A build-time variable. It is not in the running container unless you copy it into ENV. Secrets passed as ARG still land in history.

16. What is a multi-stage build?

One stage compiles, a later stage copies only the binary into a small runtime image. The compiler never ships.

17. What is a shell form versus exec form?

Shell form runs through a shell, so signals may not reach your process. Exec form is a JSON array and is the one you want for PID 1.

18. What is PID 1 in a container?

Your process. It must reap zombies and handle SIGTERM, or a stop waits until Docker kills it.

19. What is docker stop?

It sends SIGTERM, waits, then SIGKILL. An app that ignores SIGTERM is slow to stop and can lose work.

20. What is a volume?

Storage that outlives the container. A named volume is managed by Docker. A bind mount maps a host path.

21. What is a bind mount?

A host directory visible in the container. Useful in development. Risky in production because the container can write the host.

22. What is an anonymous volume?

A volume with no name, created from a VOLUME instruction. It is easy to lose track of. Name the volumes you care about.

23. What is a network in Docker?

A bridge network gives containers names they can resolve. The default bridge does not resolve names. User-defined bridges do.

24. What is -p?

It publishes a container port on a host port. EXPOSE in the Dockerfile only documents the port. It does not publish it.

25. What is EXPOSE?

Documentation and a hint to tools. It does not open the port on the host.

26. What is docker compose?

A file that describes several containers, networks, and volumes, and starts them together.

27. What is depends_on?

Start order. It does not wait until the app is ready. A healthcheck or a retry in the client does that.

28. What is a healthcheck?

A command Docker runs to mark the container healthy or unhealthy. Orchestrators use it to decide when to send traffic.

29. What is docker logs?

The process stdout and stderr. An app that writes only to a file inside the container looks silent.

30. What is docker exec?

A second process in a running container. Useful for debugging. It is not how the app should be administered in production.

31. What is an image registry?

A store of images, such as Docker Hub, ECR, or ACR. CI pushes. Nodes pull.

32. What is docker login?

It stores credentials for a registry. In CI, use a short-lived token. Do not bake the token into the image.

33. What is a private image pull?

The node or the user must be logged in, or the pull returns denied. The image name must include the registry host.

34. What is an image name?

registry/repository:tag. Missing the registry means Docker Hub. A typo looks like a missing repository.

Intermediate

35. What is a layer cache in CI?

Reuse of unchanged layers so a rebuild is fast. Copy the lockfile and install dependencies before you copy the rest of the source.

36. Why copy the lockfile first?

Source changes every commit. Dependencies do not. Installing them in an earlier layer keeps that layer cached.

37. What is a non-root user?

A USER instruction so the process is not root. If an attacker gets a shell, they are not root in the container.

38. What is a read-only root filesystem?

The container cannot write its own image layers. Give it a tmpfs or a volume for the paths it must write.

39. What is a capability?

A slice of root power, such as NET_BIND_SERVICE. Drop all capabilities and add back the one you need.

40. What is --privileged?

Nearly full access to the host. Avoid it. It defeats the point of a container.

41. What is a Docker socket mount?

The container can talk to the daemon and start other containers, including privileged ones. Treat it as root on the host.

42. What is BuildKit?

The modern builder. It enables better cache, secrets that do not stay in layers, and multi-platform builds.

43. What is a build secret?

A value mounted only during one RUN, such as a package token. It is not copied into the image. Prefer it over ARG.

44. What is docker buildx?

The BuildKit client. It can build for more than one CPU architecture and push a manifest list.

45. What is a manifest list?

One tag that points at several images, one per architecture. The node pulls the one that matches.

46. What is QEMU in a build?

An emulator so an amd64 builder can produce an arm64 image. It is slow. A native runner is faster and fails less often.

47. What is a multi-arch CI pattern?

Build each architecture on a matching runner, then assemble the manifest. Do not emulate unless you have only one kind of runner.

48. What is a distroless image?

An image with your binary and almost no shell or package manager. Smaller and harder to debug. Keep a debug variant if you need a shell.

49. What is a slim image?

A Debian or similar image with fewer packages. Smaller than the full image, still enough of a distribution to patch.

50. What is Alpine?

A small distribution using musl. Images are small. Some binaries built against glibc fail in surprising ways.

51. What is a scratch image?

An empty base. Only a static binary belongs there. There is no shell, no certificates, and no package manager.

52. What is a CA certificate in an image?

HTTPS calls fail without the system trust store. Distroless and scratch images need the certificates copied in.

53. What is apt-get in one RUN?

Update, install, and clean in the same instruction so the package index is not a permanent layer. Separate RUNs leave the index behind.

54. What is a pinned package version?

You know what you built. An unpinned install changes when the mirror changes. Pin the application. Rebuild on a schedule for patches.

55. What is a vulnerability scan?

A tool that matches packages to known CVEs. A critical finding in a base image means a rebuild, not a waiver by habit.

56. What is a parent image digest pin?

FROM image@sha256:.... You update it on purpose when you want patches. A floating tag updates whenever the build happens.

57. What is docker system prune?

It deletes unused data. On a laptop it frees disk. On a shared builder it can delete a cache you still wanted.

58. What is a dangling image?

A layer with no tag, left after a rebuild. Prune removes it. A tag you still use is not dangling.

59. What is an entrypoint script?

A shell script that writes config from environment variables, then execs the real process. End with exec so signals reach the app.

60. What is a zombie process?

A child that exited and was not waited on. A shell PID 1 that does not reap them leaves zombies. Use an init or exec the app.

61. What is tini or dumb-init?

A tiny init that reaps zombies and forwards signals. Use it when your app does not handle PID 1 correctly.

62. What is a stop grace period?

How long the orchestrator waits after SIGTERM. Set it longer than the app's shutdown. A short grace becomes a SIGKILL and a dropped request.

63. What is a restart policy?

Whether Docker starts the container again when it exits. An orchestrator such as Kubernetes has its own restart rules. Do not stack surprises.

64. What is docker compose for tests?

A database and the app, started the same way on every laptop. CI can use the same file. It is not a production orchestrator.

65. What is a compose profile?

A way to start optional services, such as a debugger, only when asked. The default path stays small.

66. What is a bind-mounted source in compose?

The laptop's code appears in the container so you can edit without rebuilding. Production images copy the code at build time.

67. What is a target in a multi-stage Dockerfile?

The stage name you build. CI builds the runtime target. Developers can build a test target that still has the compiler.

Advanced

68. What is a small attack surface?

Fewer packages means fewer bugs and fewer tools for an attacker who gets a shell. Multi-stage builds and non-root users are the usual path.

69. What is a read-only /tmp?

Some apps need to write there. Mount a tmpfs on /tmp if the root filesystem is read-only.

70. What is a user namespace?

A mapping so root in the container is an unprivileged user on the host. It is extra isolation. Kubernetes has its own controls.

71. What is seccomp?

A filter on which system calls the container may make. The default Docker profile blocks many dangerous calls. Do not disable it without a reason.

72. What is AppArmor or SELinux?

A host policy that confines the container further. A denial looks like a mysterious permission error. Check the audit log before you set privileged.

73. What is a logging driver?

Where Docker sends stdout. json-file is the default and can fill the disk. In a cluster, the orchestrator collects logs and the driver matters less.

74. What is log rotation?

A max size and file count on the json-file driver. Without it, a chatty container fills the node disk and every container suffers.

75. What is a resource limit in Docker?

--memory and --cpus cap the container. Without a memory limit, one container can make the host start killing processes.

76. What is OOMKilled?

The process exceeded its memory limit, or the node ran out. Raise the limit only after you know the app is not leaking.

77. What is a CPU limit?

The container is throttled, not killed. Latency goes up. A missing CPU request on a cluster is a different problem, but the symptom feels the same.

78. What is docker inspect?

The JSON of a container or image: mounts, env, command, and network. Use it when the run command and the reality disagree.

79. What is a label?

Metadata on an image, such as the Git commit and the source repository. OCI image labels make an image traceable.

80. What is an OCI image?

The open standard Docker images follow. Other tools, such as podman and Kubernetes, run the same images.

81. What is podman?

A daemonless engine that runs OCI images. The CLI is close to Docker. Kubernetes does not care which tool built the image.

82. What is a containerd?

The runtime many clusters use under Kubernetes. Docker Desktop includes a daemon. The node usually runs containerd, not the Docker daemon.

83. What is nerdctl or crictl?

CLIs that talk to containerd. On a node, crictl inspects the runtime. docker commands may not exist there.

84. What is an image pull policy?

A Kubernetes setting, not a Docker one. IfNotPresent skips a pull when the tag is already on the node. That hides updates to a moving tag.

85. What is a registry cache?

A place CI stores build cache. The next build pulls the cache and skips unchanged steps. It is not the runtime image.

86. What is SBOM?

A software bill of materials: the packages inside the image. Generate it in CI and store it with the digest so you can answer what you shipped.

87. What is image signing?

A signature over the digest. Admission can reject an image the pipeline did not sign. Signing a tag without a digest is weaker.

88. What is a provenance attestation?

A statement of how the image was built: which commit and which builder. It sits beside the signature.

89. What is a non-deterministic build?

The same source produces different bytes because of a timestamp or a floating download. Pin versions and set source dates if you need reproducible images.

90. What is a HEALTHCHECK that hits localhost?

It proves the process listens. It does not prove a dependency is up. Keep the check cheap and local, and let the app fail if the database is down.

91. What is a bad healthcheck?

One that loads the whole app or takes longer than the interval. The daemon then marks a busy app unhealthy and restarts it, which makes it busier.

92. What is docker compose down -v?

It removes containers and named volumes. The data is gone. Do not run it against a database you meant to keep.

93. What is a bridge versus host network?

Bridge isolates the container network. Host shares the host network namespace. Host mode skips port publishing and weakens isolation.

94. What is DNS inside a user-defined network?

Containers reach each other by service name. The name is the compose service, not the image name.

95. What is an extra_hosts entry?

A line in the container's hosts file. Use it for a lab name. It does not belong in a production image.

96. What is a secrets service in Compose?

A way to mount a secret as a file. Prefer a file mount over an environment variable, which is visible in inspect.

97. Why are environment secrets weak?

They show up in docker inspect, in crash dumps, and in child processes. Files with tight permissions are better. A secret manager is better still.

98. What is a final stage USER after apt?

Packages install as root. The last USER must be the runtime user, or the process stays root no matter how small the image is.

99. What is a file owned by root in a non-root container?

The app cannot write it. chown in the same layer as the copy, or the app fails at runtime with permission denied.

100. What should a production Dockerfile avoid?

latest tags, secrets in ARG, a full compiler in the final stage, root, and a context that includes the whole home directory.
