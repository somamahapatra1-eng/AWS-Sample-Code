Terraform: 100 interview questions

Thirty-four beginner questions, thirty-three intermediate, and thirty-three advanced. Each one has a direct answer.

Beginner

1. What is Terraform?

A tool that builds a plan from configuration and calls cloud APIs until reality matches that plan. The language is HCL.

2. What is OpenTofu?

An open-source fork of Terraform that reads the same language and state. Many teams use it as the engine while the workflow stays plan and apply.

3. What is a provider?

The plugin that talks to one API, such as AWS or Azure. The configuration declares which provider and version.

4. What is a resource?

One object Terraform creates and then owns, such as a subnet or a role. The next apply updates or deletes it if the config changed.

5. What is a data source?

A read-only lookup of something that already exists. Use it when another team owns the network and you only need its id.

6. What is state?

The file that maps your config addresses to real object ids. Lose it, and Terraform no longer knows what it created.

7. Why is local state a bad default for a team?

It lives on one laptop, has no lock, and is easy to delete. Use a remote backend with locking.

8. What is a backend?

Where state is stored: an S3 bucket, an Azure storage account, or another service. The backend block does not create that storage. It must already exist.

9. What is state locking?

A lock so two applies cannot run at once. S3 uses a lock table. Azure blob storage can lock the blob. Skipping the lock corrupts state.

10. What is terraform init?

It downloads providers and modules and configures the backend. Run it again when those change. It does not change the cloud.

11. What is terraform plan?

A preview of creates, updates, and deletes. Read it. Apply runs that plan.

12. What is terraform apply?

It executes the plan. In automation, apply a saved plan file so what you approved is what runs.

13. What is terraform destroy?

A plan that deletes everything in that state. Protect production state and require a second confirmation.

14. What is a module?

A folder of configuration you call from more than one place. The caller passes inputs and reads outputs.

15. What is a root module?

The folder where you run init and apply. Child modules are called from it. Each root has its own state.

16. What is a variable?

An input. Declare the type and a description. Do not put secrets in a default committed to Git.

17. What is an output?

A value printed or passed to another root through a remote state data source. Mark secrets as sensitive.

18. What is a local value?

A computed name inside the module. It is not an input and not stored as its own resource.

19. What is count?

It makes several copies from a number. Removing an item in the middle renumbers the rest and can destroy the wrong one.

20. What is for_each?

It makes one copy per key in a map or set. Keys stay stable. Prefer it over count for anything you might remove.

21. What is a resource address?

The path Terraform uses in state, such as module.network.azurerm_subnet.app. Plans and state show these addresses.

22. What is terraform state mv?

It renames an address in state without touching the cloud. Use it when you move a resource into a module and do not want a destroy.

23. What is a moved block?

A config way to record that rename. The next plan moves state instead of replacing the object. Prefer it over a one-off command.

24. What is terraform import?

It binds an existing cloud object to an address. You still write the config to match, or the next plan will change it.

25. What is an import block?

Import written in config so a review can see it. The plan shows the import before anything changes.

26. What is drift?

The cloud changed outside Terraform. The next plan tries to undo that change. Either accept it into config or let apply put it back.

27. What is terraform refresh?

It updates state from the cloud without changing the cloud. Modern plan does this as part of planning.

28. What is -target?

It limits a plan to some addresses. Dependencies can be skipped and leave a half-applied picture. Use it to recover, not as the normal path.

29. What is -replace?

It forces one resource to be destroyed and created again. Use it when an object is wedged and a normal update will not fix it.

30. What is a tainted object?

State marks it to be replaced on the next apply. Replace is the current way to ask for the same thing.

31. What is a lifecycle block?

Rules on one resource: create_before_destroy, prevent_destroy, or ignore_changes.

32. What does prevent_destroy do?

Apply fails instead of deleting that resource. Use it on databases and clusters. It does not stop a human with console access.

33. What does ignore_changes do?

Terraform stops planning those fields. Use it when a controller owns them, such as an autoscaler changing capacity.

34. What does create_before_destroy do?

The new object is created first, then the old one is removed. Needed when a name cannot have a gap, and when the name can exist twice.

Intermediate

35. What is depends_on?

An explicit edge when Terraform cannot see the dependency. A hidden dependency is an IAM policy that must exist before a pod starts, even if no attribute is referenced.

36. What is a provisioner?

A script Terraform runs on create. It fails in odd ways and does not re-run when you expect. Prefer cloud-init or a real config tool.

37. What is a null_resource?

A placeholder that exists to run a provisioner. It is a smell. Replace it with a real resource or a separate step.

38. What is a provider alias?

A second configuration of the same provider, such as another region. Resources choose it with the provider argument.

39. What is a required version?

The Terraform and provider versions the module allows. Pin them so a laptop and CI do not use different plugins.

40. What is a lock file?

.terraform.lock.hcl records provider hashes. Commit it so every machine downloads the same build.

41. What is a semantic version constraint?

~> 5.1 allows 5.1 and later 5.x, not 6.0. A wide open constraint will break you on a major release.

42. What is a major provider upgrade?

Read the changelog. Attributes get renamed and resources get replaced. Plan in a test account first.

43. What is a workspace?

A named state slot in one backend, such as dev and prod. Separate directories or separate backends are clearer when the shapes differ.

44. When are workspaces a poor fit?

When dev and prod are not the same config. A flag that turns off half the resources is harder to read than two roots.

45. What is a remote state data source?

One root reads another root's outputs. Lock the network root so the application root cannot change it. Do not read the whole state if outputs are enough.

46. What is a sensitive variable?

Terraform redacts it in the plan. State still stores the value. Protect the state file as if it were a secret.

47. What is a secret in config?

A bad place. Pass it from a secret manager at apply time, or have the cloud resource read the secret itself.

48. What is terraform validate?

A syntax and type check with no cloud calls. Run it in CI before plan.

49. What is terraform fmt?

It rewrites files to a standard layout. CI should fail when fmt would change a file.

50. What is TFLint or a policy tool?

A linter or a policy check, such as OPA or Checkov, that catches an open security group before plan. It does not replace plan.

51. What is a module version?

A Git tag or a registry version on the module source. A branch name moves under you. A tag does not.

52. What is the public registry?

A host of published modules. Read them. Pin the version. A module that creates more than you named is a surprise in the plan.

53. What is a child module output?

The only values the parent should use. Reaching into module.child.resource.attr works and makes refactors painful. Output it.

54. What is a variable validation?

A condition that fails init or plan when the value is nonsense, such as an empty name. Fail early.

55. What is a nullable or optional attribute?

An object type can allow a missing field. Use it for a block callers usually skip. Do not use a string that means three different things.

56. What is a dynamic block?

A loop that builds nested blocks, such as several ingress rules. If the dynamic block is unreadable, make a smaller resource instead.

57. What is a splat?

A shorthand that takes one attribute from a list of objects. It hides a loop. Fine for a short list, noisy when the list can be empty.

58. What is try?

It returns the first value that does not error. It can hide a typo. Prefer a known default.

59. What is coalesce?

The first non-null value. Useful for a name that may be set in two places. Document the order.

60. What is a ternary?

A one-line if. Nested ternaries are how modules become unreadable. Use a local with a clear name.

61. What is for in HCL?

A list or map comprehension. Use it to turn a list of names into a map of resources for for_each.

62. What is a type constraint object?

A variable that must have named fields. Callers get an error on a misspelled field instead of a null deep in the plan.

63. What is terraform console?

A prompt that evaluates expressions against state. Handy to test a function. It is not how you change the cloud.

64. What is terraform graph?

A dependency graph. Use it when you do not understand why an object is created first. It gets large quickly.

65. What is a saved plan?

plan -out=file writes the exact actions. apply file runs those actions. CI should pass the file, not run a second plan at apply time.

66. What is a speculative plan?

A plan from a merge request that does not apply. It shows reviewers the destroy lines before they merge.

67. What is a destroy in a plan?

A line that will delete an object. Treat any unexpected destroy as a stop. Name changes and subnet changes cause them.

Advanced

68. What is terraform workspace select?

It switches which state slot commands use. Forgetting the switch applies dev config to prod state, or the reverse. Directories are harder to mix up.

69. What is a partial apply?

Apply failed in the middle. State matches what was created. Fix the error and apply again. Do not edit state unless you know the object is gone.

70. What is state rm?

It forgets an object without deleting it. Use it when you are moving ownership to another root. The cloud object stays.

71. What is terraform state pull?

It prints state. That file contains secrets. Do not paste it into a ticket.

72. What is a backend migration?

init -migrate-state copies state to a new backend. Back up first. Two people doing this at once is how state forks.

73. What is a state fork?

Two state files think they own the same objects. The next apply from either one can delete them. Stop and pick one state.

74. What is a resource targeting import mistake?

The config does not match the real object, so the first plan after import wants to replace it. Adjust the config until the plan is empty.

75. What is a module refactor risk?

Moving a resource without a moved block plans a destroy and a create. For a database that is data loss. Review the addresses.

76. What is prevent_destroy not covering?

A replace still destroys. prevent_destroy blocks that too in many cases, and then you must remove the flag on purpose to replace.

77. What is a depends_on for a module?

The parent waits for the whole module. It does not create edges to individual resources inside. Use it when the module has a side effect with no output.

78. What is an output that is a secret?

Mark it sensitive. Callers still receive it. Logging the output in CI undoes the mark.

79. What is TF_LOG?

A trace of provider calls. Use it for a bug. Do not leave it on. It prints request bodies.

80. What is a provider bug versus a config bug?

If the plan is what you asked and the API rejects it, it is often a constraint the provider did not model. Read the API error before you blame the tool.

81. What is a retry on apply?

Many providers retry throttling. A conflict error may need a second apply once the first object's dependents exist.

82. What is parallelism?

How many resources change at once. Lower it when the API throttles. It does not change the graph.

83. What is a graph cycle?

A depends on B and B depends on A. Terraform refuses the plan. Break the cycle with a two-step apply or a different design.

84. What is create_before_destroy with a fixed name?

The new object cannot exist until the old name is freed, so the flag errors. Use a name that can change, or accept a gap.

85. What is a name prefix?

A name that starts with a string and ends with a hash. It allows create_before_destroy. The cloud name is not the config name.

86. What is terraform test?

A way to run assertions against a module with a plan or a real apply. Use it for modules you publish. It is not a substitute for a review of the production plan.

87. What is a mock provider?

A test double so a module test does not create real accounts. Mocks drift from the real API. Keep one real plan in a sandbox.

88. What is a policy as code check?

A rule such as encryption must be on, run against the plan. It catches the case the linter cannot see because the value came from a variable.

89. What is a cost estimate on a plan?

A tool that prices the plan. It is approximate. A NAT gateway and a load balancer dominate small clusters. Read the line items.

90. What is a destroy-time provisioner?

A script on delete. If it fails, the object is stuck in state. Avoid it.

91. What is a precondition?

A check that fails the plan when an assumption is false, such as a subnet that is too small. It runs before the cloud changes.

92. What is a postcondition?

A check after apply that the result matches a rule. Use it when the cloud fills in a value you need to trust.

93. What is a check block?

An assertion that can warn without failing, or fail, depending on how you write it. Use it for invariants that are not one resource.

94. What is a removed block?

It tells a newer Terraform to drop an address from state without deleting the cloud object, or to destroy it, depending on the settings. Read the plan either way.

95. What is a deprecated attribute?

The provider still accepts it and warns. Fix it before the next major version removes it and the plan stops.

96. How do you review a 2,000-line plan?

Search for destroy and replace first. Then look at security groups, IAM, and names. A green CI plan that nobody read is how outages ship.

97. What is a module monolith?

One root that creates the network, the cluster, the database, and the app. A bad apply can touch all of them. Split roots on change rate and on who owns the blast radius.

98. What is a layered root?

Network in one state, cluster in another, apps in a third. Each apply is smaller. The cost is remote-state wiring and order.

99. What belongs in core_config versus the environment file?

Defaults a caller never changes can live beside the module. Names, CIDRs, and which features are on belong in the environment file the operator edits.

100. How do you upgrade a module safely?

Pin the old version, read the changelog, plan in a sandbox, look for replaces, then bump one environment. Do not bump every environment in one merge.
