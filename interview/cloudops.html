CloudOps: 100 interview questions

Thirty-four beginner questions, thirty-three intermediate, and thirty-three advanced. Each one has a direct answer.

Beginner

1. What is CloudOps?

Running systems on a cloud: change, capacity, cost, security, and repair. The cloud provider runs the hardware. You run everything you configured.

2. What is the shared responsibility model?

The provider secures the cloud. You secure what you put in it: identities, data, network rules, and the guest operating system when you own the virtual machine.

3. What is an account or subscription boundary?

A blast-radius wall. Production and non-production should not share one. A mistake in a lab should not delete production.

4. What is a landing zone?

The baseline accounts, networks, identity, and logging that every application inherits. Applications should not invent their own version.

5. What is infrastructure as code in operations?

The running cloud matches a reviewed file. A click in the console is drift unless the file is updated to match, on purpose.

6. What is drift?

Reality and the recipe disagree. Detect it with a scheduled plan. Decide whether the recipe or the console was wrong. Do not ignore it.

7. What is a change record?

Who changed what, when, and why. CloudTrail or Activity Log is the record of API calls. A ticket without the API id is incomplete.

8. What is an emergency change?

A break-glass path that is still logged and reviewed the next day. Skipping the log because it is urgent is how the urgent change becomes the next incident.

9. What is a maintenance window?

When planned disruption is allowed. Patching and upgrades go here. Incidents do not wait for the window.

10. What is patching?

Applying vendor fixes to images, nodes, and managed services. Replace images when you can. In-place patching of a snowflake does not scale.

11. What is a golden image?

A hardened machine image rebuilt on a schedule. Nodes boot from it. SSH-ing in to patch one node creates a machine you cannot rebuild.

12. What is immutable rollout?

New instances from the new image, then the old ones go away. A health check gates the shift. You do not patch a live box and hope.

13. What is capacity?

How much CPU, memory, storage, and network you can use before users feel it. Quotas are not capacity. Quotas are a ceiling you can hit by surprise.

14. What is a service quota?

The account limit. A scale-out fails at the quota even when the autoscaler is correct. Raise quotas before the launch, not during it.

15. What is autoscaling?

Add or remove capacity from a signal. It needs a ceiling, a cooldown, and a test. An autoscaler with no maximum is a bill with no maximum.

16. What is a scaling limit?

The maximum you are willing to pay and that the dependencies can survive. The database often falls over before the web tier's autoscaler stops.

17. What is headroom?

Spare capacity for a failure or a spike. Running at 95 percent looks efficient and fails the moment one node dies.

18. What is multi-AZ?

The service runs in more than one availability zone. A zone failure then removes a share, not the whole system. One zone with a backup in another region is a different design.

19. What is a region failure plan?

What you do if a whole region is gone. Multi-AZ does not answer it. You need a second region, or a written decision that you will wait.

20. What is RPO?

Recovery point objective: how much data you can lose. A backup every night means up to a day. Say the number out loud before you promise it.

21. What is RTO?

Recovery time objective: how long until the service is back. A backup you have never restored has an unknown RTO.

22. What is a backup?

A copy you can restore. A snapshot in the same account, with the same credentials, is not safe from a bad actor or a bad script in that account.

23. What is a restore test?

You actually bring the data back on a schedule. An untested backup is a rumor.

24. What is snapshot versus backup?

A snapshot is quick and often in the same system. A backup is a copy with its own retention and, ideally, its own account. Use both when the data matters.

25. What is retention?

How long copies are kept. Too short and you cannot recover last month's delete. Too long and you pay forever and keep data you no longer have a right to hold.

26. What is replication?

A live copy in another place. It copies mistakes too, including a dropped table. Replication is not a backup.

27. What is failover?

Traffic moves to the healthy copy. It should be rehearsed. A DNS failover with a long TTL is slower than the diagram suggests.

28. What is a health check for failover?

A check that matches user pain. A check that only proves a port is open will send users to a broken app.

29. What is DNS TTL?

How long resolvers cache the answer. A low TTL makes failover faster and increases query load. Change it before the incident, not during it.

30. What is a certificate expiry?

TLS stops on a date. Alert weeks ahead. Automate renewal. A calendar reminder is how last year's outage happened.

31. What is a secret rotation?

A new credential replaces the old one, and the old one is revoked. Rotation that only adds a second secret and never revokes the first is collection, not rotation.

32. What is a secret store?

A service built to hold credentials, with audit and access policy. A file in a repository or a chat message is not a store.

33. What is least privilege?

The identity can do the one job and nothing else. Admin on the subscription because it was faster is how a small bug deletes the network.

34. What is a managed identity or a role?

The compute gets credentials from the platform. There is no password to copy. Prefer it over a key in a variable.

Intermediate

35. What is a long-lived access key?

A secret that works until someone remembers to delete it. Avoid it for workloads. A human break-glass key should be rare and alarmed.

36. What is CloudTrail or Activity Log?

The API audit. Turn it on in every account, send it to a separate account, and alert on the controls being disabled.

37. What is a log archive account?

Logs live where the application team cannot delete them. An attacker who owns the app account should not own the evidence.

38. What is an SLO for operations?

A target for the platform, such as the share of node launches that succeed. Product SLOs sit on top. If the platform misses, say so.

39. What is an error budget in operations?

How much platform failure you will spend before you stop risky changes. A budget nobody is allowed to spend is a slogan.

40. What is toil?

Repetitive manual work tied to running the service. Track it. Automate the weekly kind. Keep humans on the judgment.

41. What is an on-call shift?

A bounded time when a named person responds. Hand off with open incidents written down. A shift with no backup is a hope.

42. What is paging versus ticketing?

A page is for user pain happening now. A ticket is for tomorrow. CPU at 70 percent with happy users is a ticket.

43. What is a runbook?

The steps for a known page, including how to tell that it is this problem and how to back out. Review it after you use it.

44. What is a stale runbook?

The commands do not match the system. Following it makes the incident worse. If a step fails, stop and think. Update the page after.

45. What is an incident timeline?

What happened, in order, with times. Write it during the incident. Memory after midnight is a poor log.

46. What is severity?

Impact, not how hard the bug is. A tricky bug that affects nobody is not sev-1. A one-line bug that takes payments down is.

47. What is a postmortem?

What failed in the system, what you will change, and who owns the change. Blaming a person does not stop the next one.

48. What is an action item?

A change with an owner and a date: an alert, a test, a quota, or a guardrail. 'Be more careful' is not an action item.

49. What is observability?

Logs, metrics, and traces that let you ask a question you did not predict. A single CPU graph is not observability.

50. What are golden signals?

Latency, traffic, errors, and saturation. Alert on symptoms users feel. Diagnose with the rest.

51. What is a dashboard?

A view for a question you ask often. It is not an alert. Nobody stares at a dashboard at 3 a.m. unless a page sent them there.

52. What is cardinality?

How many unique metric series you create. A label with a user id will bankrupt the metrics bill and slow the queries.

53. What is a log that is too quiet?

The request failed and nothing was written. Log the error, the id, and the dependency. Do not log the password or the card number.

54. What is sampling?

You keep a fraction of traces. You need it at high volume. Sample in a way that still keeps the errors.

55. What is a synthetic check?

A probe you send, such as a login every minute, from outside the cluster. It catches a failure your inside metrics cannot see.

56. What is a real-user metric?

Timing from actual clients. Synthetics miss a bad ISP or a huge page. Use both.

57. What is saturation?

A resource running out: connections, disk, pool threads, or IPs. Utilization can look fine while a pool is exhausted.

58. What is a connection pool leak?

Connections are taken and not returned. The app then waits. The CPU graph stays calm. The pool metric is the one that pages.

59. What is disk full on a node?

Logs or images filled the disk. The kubelet evicts pods. A log limit and an image prune are the fix, not a bigger disk forever.

60. What is NTP or time skew?

Certificates and tokens fail when clocks disagree. Time looks boring until authentication breaks in one region.

61. What is a cost allocation tag?

A tag that says which team owns the spend. Without it, the bill is one number and nobody reduces it.

62. What is FinOps?

The practice of making cost a shared decision: visibility, budgets, and a reason to pick a cheaper design. It is not only a monthly spreadsheet.

63. What is a budget alert?

A notice before the month is over. An alert at 100 percent tells you the money is already gone.

64. What is rightsizing?

A smaller instance that still meets the SLO. Buying a large one and using 5 percent is a standing waste.

65. What is a reserved instance or a savings plan?

A discount for a commitment. Buy it for the baseline you know you will run. Do not reserve a spike.

66. What is spot or preemptible capacity?

Cheap capacity that can disappear. Good for workers that can retry. Bad for the only copy of a service.

67. What is an idle load balancer?

An hourly charge with no traffic. Forgotten lab resources are a large share of surprise bills.

Advanced

68. What is an unattached disk?

A volume nobody is using. It still bills. A cleanup job should list them, skip the ones tagged keep, and delete only after a waiting period.

69. What is a stopped virtual machine?

Compute may stop. Disks and addresses often do not. A stopped fleet is not a free fleet.

70. What is a schedule to stop non-production?

Dev machines off at night. Tag the ones that must stay up. Measure the saving. Do not schedule production databases this way.

71. What is a public IP you did not mean?

An attack surface and sometimes a charge. Inventory them. Private endpoints cover a lot of cloud API traffic.

72. What is a security group of 0.0.0.0/0?

The port is open to the internet. Sometimes that is the website. Often it is a database someone opened to test and forgot.

73. What is a network path check?

You can explain how a user reaches the app: DNS, load balancer, subnet, security rule, and health check. If you cannot draw it, you cannot debug it.

74. What is a private endpoint?

A private address for a cloud API inside your network. It removes the need for a public path to that API. DNS must point at it or you still go public.

75. What is split horizon DNS?

The same name resolves to a private address inside the network and a public one outside. A wrong zone link sends traffic the long way, or nowhere.

76. What is a certificate on the wrong name?

The load balancer presents a name the client does not expect. Browsers fail. Health checks that skip TLS verification still pass.

77. What is a WAF?

A filter on HTTP. It blocks common attacks and can block your own app. Put it in front of public sites and test the rules before you enforce them.

78. What is DDoS protection?

The provider absorbs volumetric attacks at the edge. You still need application limits, or a small flood of real-looking requests will pass the network layer.

79. What is rate limiting?

A cap per caller. It protects the dependency. A limit that is lower than real traffic is an outage you caused.

80. What is a circuit breaker?

The client stops calling a dependency that is failing, then tries again later. It prevents a pile-up. It needs a fallback the user can survive.

81. What is a timeout?

How long you wait. A missing timeout turns a slow dependency into a stuck thread pool. Set it. Make it shorter than the caller's timeout.

82. What is a retry storm?

Every client retries at once. The dependency never recovers. Retry with backoff and jitter, and limit the number of tries.

83. What is idempotency?

Doing the operation twice has the same result as once. Retries are safe only when the operation is idempotent, or when you send an idempotency key.

84. What is a queue as a buffer?

Producers keep working when consumers are slow. The queue depth is the metric. An unbounded queue hides a consumer that has been dead for a day.

85. What is dead-letter?

Messages that failed too many times go aside for a human. They should alarm. A dead-letter nobody reads is a silent data loss.

86. What is a deployment marker?

A line on the graphs at the time of the release. It makes a bad deploy obvious. Without it, people blame the network.

87. What is a rollback criterion?

The number that means you go back: error rate, latency, or a failed check. Decide it before the deploy, not while you are hoping it recovers.

88. What is a feature flag in operations?

You can turn the change off without a redeploy. The flag service is now a dependency. If it is down, know the default.

89. What is configuration drift in an app?

The environment variable in production is not the one in Git. Print the effective config, minus secrets, at startup, or you will debug the wrong system.

90. What is a canary in operations?

A slice of real traffic on the new version, with a comparison. If you cannot see the slice, you do not have a canary. You have a partial outage.

91. What is a game day?

You cause a failure on purpose: one zone, one database replica, one expired certificate. The goal is a runbook that worked, or a list of what to fix.

92. What is chaos engineering?

An experiment with a hypothesis and a stop button. Unplanned breakage is an incident, not chaos engineering.

93. What is a dependency map?

What you call, and what calls you. An incident in a system you forgot you use will confuse the timeline. Keep the map near the service.

94. What is a vendor status page?

How you tell a cloud fault from your fault. Check it, and still debug your change. Both can be true.

95. What is a quota increase lead time?

Some limits are instant and some take days. Ask before the marketing launch, not when the autoscaler is stuck.

96. What is a regional service versus a zonal one?

A zonal disk dies with the zone. A regional database fails over. Know which you bought. The product name is not the architecture.

97. What is an availability SLA?

The provider's promise and the credit if they miss it. Your users do not care about the credit. Design for the failure anyway.

98. What is error budget burn?

You are consuming the month's allowed downtime too fast. Stop shipping risk. Fix the burn. A launch on a burned budget is a choice to miss the SLO.

99. What is a capacity test before a sale?

You know the ceiling in orders per minute. Marketing should not learn it from the incident channel.

100. How do you hand a system to on-call?

A dashboard, a page that fires on a real symptom, a rollback, an owner, and one game day. Anything less is a handover of hope.
