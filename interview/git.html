Git: 100 interview questions

Thirty-four beginner questions, thirty-three intermediate, and thirty-three advanced. Each one has a direct answer.

Beginner

1. What is Git?

A distributed version control system. Every clone has the full history. You commit locally, then push to share.

2. What is a repository?

The project history: commits, branches, and tags. The working tree is the files you see. The repository is the .git directory.

3. What is a commit?

A snapshot of the tree, plus the parent commit, the author, and a message. The id is a hash of that content.

4. What is a branch?

A movable name for a commit. It is not a copy of the files. Two branches can point at the same commit.

5. What is HEAD?

The commit you have checked out. Usually it is the tip of a branch. If you check out a raw commit, HEAD is detached.

6. What is a detached HEAD?

You are not on a branch. A new commit can be lost when you leave, unless you name a branch first.

7. What is the staging area?

The index. git add copies changes there. git commit records what is staged, not every edit in the working tree.

8. What is git status?

What is staged, what is modified, and which branch you are on. Read it before you commit.

9. What is git diff?

Unstaged changes. git diff --staged shows what the next commit will contain.

10. What is git add -p?

Stage hunks, not the whole file. It keeps a drive-by edit out of the commit.

11. What is a commit message?

The first line says what changed and why, in the imperative. The body explains anything the diff cannot.

12. What is git log?

History from HEAD backward. --oneline --graph is the readable form. A log that is only 'fix' is useless later.

13. What is git show?

One commit's message and diff. Use it to review what you are about to push.

14. What is a remote?

A named URL, usually origin, where you push and fetch. It is not automatically up to date.

15. What is git fetch?

It downloads new commits and updates remote-tracking branches. It does not change your files.

16. What is git pull?

Fetch plus merge, or fetch plus rebase if you configured that. Know which one you have. A surprise merge commit is usually a pull.

17. What is a remote-tracking branch?

origin/main is your last fetch of their main. It moves when you fetch, not when they push.

18. What is git push?

It sends your commits and moves the remote branch. The remote rejects the push if you do not have the latest and a fast-forward is required.

19. What is a fast-forward?

The branch only moves forward. No merge commit is needed because your tip is a descendant of theirs.

20. What is a merge?

A commit with two parents that joins two lines. History keeps both. Conflicts are resolved in that commit.

21. What is a rebase?

Your commits are replayed on top of another tip. History looks linear. Do not rebase commits other people have already pulled.

22. What is the golden rule of rebase?

Do not rewrite published history. Rebase your own unpushed commits. Rewriting main forces everyone else to recover.

23. What is a merge conflict?

Both sides changed the same lines. Git stops. You edit the file, remove the markers, add it, and continue the merge or rebase.

24. What are conflict markers?

<<<<<<<, =======, and >>>>>>>. If you commit them, the file is broken and the build should catch it.

25. What is git merge --abort?

It returns you to the state before a merge you do not want to finish.

26. What is git rebase --continue?

After you fix a conflict during a rebase, it replays the next commit. --abort gives up the rebase.

27. What is a fast-forward merge?

The branch pointer moves. There is no merge commit. git merge --ff-only fails if a merge commit would be required, which is what main protection wants.

28. What is a squash?

Many commits become one. The branch history is discarded in the merge. Use it for a messy personal branch. Do not squash shared history you still need to bisect.

29. What is git revert?

A new commit that undoes an older commit. History is not rewritten. This is the safe way to undo something already on main.

30. What is git reset?

It moves your branch pointer. --soft keeps changes staged. --mixed keeps them in the working tree. --hard throws the changes away.

31. What is reset --hard risk?

Uncommitted work and commits that no other ref points at can be lost. It does not affect the remote until you push.

32. What is a force push?

It overwrites the remote branch. --force-with-lease refuses if someone else pushed since you fetched. Prefer the lease. Bare --force does not.

33. What is a protected main?

The server rejects force push and direct push. Changes come through a pull request. Protection on the server matters more than a team agreement.

34. What is a pull request?

A review of commits before they join the base branch. The name on GitHub is pull request. Git itself only has branches.

Intermediate

35. What is git stash?

A shelf for uncommitted work. stash pop brings it back. A stash is easy to forget. A commit on a temporary branch is harder to lose.

36. What is git cherry-pick?

It copies one commit onto your branch as a new commit. Use it to move a fix. Do not cherry-pick a long chain if a merge would keep the history clearer.

37. What is a tag?

A name for a commit that does not move, used for releases. A lightweight tag is a name. An annotated tag has a message and an author.

38. What is git fetch --tags?

Tags are not branches. A normal fetch may not get every tag, depending on config. Releases should be fetched on purpose.

39. What is a detached tag checkout?

You are looking at the release, not a branch. Creating a fix requires a branch from that commit.

40. What is HEAD~1?

The first parent of HEAD. On a merge commit, the first parent is the branch you merged into. HEAD^2 is the second parent.

41. What is git reflog?

A local history of where HEAD and branches pointed. It is how you recover a reset you regret. It is not pushed. It expires.

42. What is git bisect?

A binary search through commits to find which one broke a test. It needs a reproducible check. Squashed history makes the result a giant commit.

43. What is .gitignore?

Files Git should not offer to add. It does not untrack a file that is already committed. Removing a secret from the tip does not remove it from history.

44. What is git rm --cached?

It stops tracking a file and leaves the copy in the working tree. Use it after you add a file to .gitignore that was committed by mistake.

45. What is a secret in history?

It is still in old commits. Rotate the secret. Rewriting history is a second step and everyone must re-clone. Rotation is the one that matters.

46. What is git blame?

Which commit last touched each line. It is a starting point, not a verdict. A formatting commit will own every line.

47. What is a hook?

A script Git runs on an event, such as pre-commit. Client hooks are local and can be skipped. A server hook or CI is the control you can trust.

48. What is a pre-commit hook?

It runs before the commit is created. Good for formatters. A developer can bypass it. CI must repeat the check.

49. What is GIT_AUTHOR versus GIT_COMMITTER?

Author is who wrote the change. Committer is who created the commit object. They differ after a rebase or a cherry-pick.

50. What is a signed commit?

A cryptographic signature that the commit came from a key. The server can require it. A signature does not mean the code is safe. It means the identity is stronger.

51. What is SSH versus HTTPS for remotes?

SSH uses a key. HTTPS uses a credential helper or a token. A token in the remote URL gets copied into files and chats. Do not put it there.

52. What is a credential helper?

A program that stores and provides the password or token. The token should not appear in git remote -v.

53. What is git clone --depth?

A shallow clone with little history. It is faster and breaks bisect and some merges. CI often uses it. Developers usually want full history.

54. What is a shallow fetch problem?

The server rejects a push or a merge because the missing base is not there. Deepen the clone or fetch unshallow.

55. What is git submodule?

A pointer to a commit in another repository. The parent stores the commit id. Forgetting to update the submodule leaves you on an old checkout.

56. What is git subtree?

It vendors another project as a subdirectory with history. Fewer moving parts than submodules, and a noisier history.

57. What is a monorepo?

Many projects in one repository. Atomic changes across them are easy. CI must learn what changed or every push builds everything.

58. What is a sparse checkout?

The working tree contains only some directories. Useful in a huge monorepo. The history is still complete unless you also use a partial clone.

59. What is a partial clone?

The server omits blobs until you need them. It saves bandwidth. Old Git servers and some tools do not support it.

60. What is Git LFS?

Large files stored as pointers in Git and as bytes in a side store. Cloning without LFS gives you the pointers, not the files.

61. What is a line ending problem?

Windows and Unix disagree on CRLF. core.autocrlf or a .gitattributes file makes diffs stable. A repo that flips every line hides the real change.

62. What is .gitattributes?

Rules per path: line endings, diff drivers, and whether a file is binary. Mark generated binaries as binary so Git does not merge them as text.

63. What is a binary file in Git?

Git stores it, but merges and diffs are useless. Large binaries belong in LFS or an artifact store, not in every commit.

64. What is git cherry?

It shows commits on your branch that are not in the upstream, by patch id. Useful before a rebase to see what would be replayed.

65. What is a patch id?

A hash of the change, ignoring commit metadata. Cherry and rebase use it to skip commits that are already applied.

66. What is an octopus merge?

A merge of more than two branches. Rare. If you need it, the history is probably too clever.

67. What is git rerere?

It reuses a recorded conflict resolution. Helpful when you rebase the same long branch many times. Turn it on before you need it.

Advanced

68. What is a worktree?

A second working directory attached to the same repository. You can have main checked out and a fix branch checked out at once, without a second clone.

69. What is git switch?

The current command to change branches. git checkout still works and also restores files, which is why it is easy to misuse.

70. What is git restore?

It throws away unstaged changes or unstages a file. It replaces the confusing uses of checkout.

71. What is git clean?

It deletes untracked files. -fd is dangerous. -n shows what it would delete. Ignored files stay unless you ask.

72. What is an upstream branch?

The remote branch your branch pushes to and pulls from. git push -u sets it. Without it, the first push must name the remote and the branch.

73. What is git push --force-with-lease?

A force push that fails if the remote moved. It protects a teammate's commits. It does not protect a commit you have not fetched.

74. What is a rebase onto main?

Your branch is replayed on the latest main. Conflicts are handled one commit at a time. The result is easier to merge and harder to share mid-rebase.

75. What is an interactive rebase?

You reorder, squash, or drop commits before anyone else has them. Do not run it on main.

76. What is fixup?

A commit marked to be squashed into an earlier one and to drop its message. Rebase --autosquash applies the marks.

77. What is a commit template?

A file Git opens as the default message. Use it to remind people to say why. It does not enforce the content.

78. What is a trailer?

A structured line in the message, such as Signed-off-by or Reviewed-by. Tools can read them. They are convention, not enforcement.

79. What is git interpret-trailers?

It adds or reads those lines. CI can require a trailer. A missing trailer should fail the check, not the honor system.

80. What is a notes ref?

Notes attached to a commit without changing its hash. They are not cloned by default. Do not hide required review information there.

81. What is git range A..B?

Commits reachable from B and not from A. The two-dot and three-dot forms differ. Three dots is the symmetric difference and surprises people in diffs.

82. What is git diff main...feature?

The changes on the feature branch since it split from main. It is the pull-request diff. Two dots includes unrelated movement of main.

83. What is a merge base?

The best common ancestor. Conflicts and three-dot diffs are computed from it. A criss-cross history makes the base ambiguous.

84. What is git log --first-parent?

It follows only the first parent of merges, so main's history hides the noise inside merged branches. Useful on a busy main.

85. What is a revert of a merge?

You must say which parent is the main line. Reverting the merge without -m produces the wrong tree. Re-merging later needs the revert to be reverted.

86. What is git replace?

A local substitution of one object for another. It is a specialist tool. Do not use it to hide history from a teammate.

87. What is filter-repo?

The current tool to rewrite history, such as removing a file from every commit. filter-branch is the old one. Everyone must re-clone after a rewrite.

88. What is a bundle?

A file that contains part of the repository. You can move commits by file when the network cannot. It is still Git data, including any secrets in those commits.

89. What is git archive?

A zip or tar of one tree, without the .git directory. It is a source package, not a clone.

90. What is a bare repository?

A repository with no working tree, used as a remote. You push to it. You do not edit files there.

91. What is a fork?

A server-side clone under your account, common on GitHub. Git does not have a fork command. Your local remote usually points at the fork, and upstream points at the original.

92. What is upstream versus origin?

Origin is where you push, often your fork. Upstream is the project you sync from. The names are convention.

93. What is git remote prune?

It deletes remote-tracking branches that the server no longer has. Your local branches stay. A stale origin/feature confuses status.

94. What is branch -d versus -D?

-d deletes a merged branch and refuses otherwise. -D deletes it anyway. You can lose unmerged commits that no other ref names. Reflog can still save you locally.

95. What is a tag that moves?

Someone deleted and recreated the tag. Builds that trusted the name now point at a different commit. Protect release tags.

96. What should a release tag point at?

The commit you built and tested, not a later commit on the branch. Move the branch. Do not move the tag.

97. How do you undo a commit that is only local?

reset --soft HEAD~1 leaves the changes staged. Use revert if the commit is already on a shared branch.

98. How do you find a deleted branch?

reflog shows the commit it pointed at. Create a branch at that hash. If you never fetched it, it was never on your machine.

99. What is git commit --amend?

It replaces the last commit that has not been shared. Amending a commit you already pushed requires a force push. Do not amend on main.

100. What is a good history for?

You can explain a change and bisect a bug. A history of squashed noise and rewritten main cannot. Keep the public history boring and true.
