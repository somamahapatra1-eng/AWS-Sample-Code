Security scans

These six scans look at different things. None of them replaces the others. A clean Sonar gate does not mean the container image is safe, and a clean image scan does not mean the source is free of an injection bug.

Scan What it reads What a failure means
2ms Files and Git history A secret is in the tree. Rotate it. Deleting the line is not enough.
Checkmarx Source code A path from untrusted input to a dangerous call, such as SQL, a command, or HTML.
Sonar Source code, tests, coverage The quality gate failed: new bugs, vulnerabilities, hotspots, or coverage below the bar.
Black Duck Lockfiles, binaries, and signatures An open-source component has a known vulnerability, or a license the policy forbids.
FOSS The open-source inventory A component is not approved, or its license obligations are not met.
Twistlock Container images, hosts, and runtime The image has a vulnerability over the threshold, malware, or a compliance break.

Where they sit in a pipeline

  1. 2ms on the commit, including history added by the branch. Stop before you compile secrets into an artifact.
  2. Checkmarx and Sonar on the source. They can run in parallel.
  3. Black Duck on the dependency lockfile or the built packages. FOSS uses that inventory for the license decision.
  4. Build the image from the commit that passed those gates.
  5. Twistlock on that image. Deploy only the digest that passed.

A waiver needs an owner and an expiry. A finding marked "not exploitable" with no reason will still be there on the next audit.

2ms

2ms is Checkmarx's secret scanner. The name is short for "too many secrets." It looks for API keys, tokens, passwords, and private keys in files and in Git history.

  • Run it on the pull request and on a schedule over the default branch. A secret committed last year is still a secret.
  • A match in history means rotate the credential, then rewrite or expire the old commit only as a second step. Rotation is the step that stops use of the leaked value.
  • High-entropy strings and known token prefixes are the usual rules. A test fixture that looks like a key should be a fake value in an allow-list, not a real key with an ignore comment.
  • Do not print the secret in the job log. The report should show the file, the commit, and the rule name.

Checkmarx

Checkmarx SAST reads source and builds a data-flow graph. It asks whether untrusted input can reach a sink: a query, a shell, a file path, or a page. It does not run the program.

  • A result names the query, the severity, the source, and the sink. Triage it. "Not exploitable" is valid when the path cannot be hit. "Confirmed" means fix the code.
  • A full scan covers the project. An incremental scan covers the change and is faster. Use a full scan on a schedule so deleted-file findings and older branches do not hide.
  • It is weak on vulnerabilities that exist only in a compiled dependency. That is Black Duck's job. It is also weak on a secret sitting in a config file. That is 2ms.
  • The scan is only as good as the language pack and the queries you enabled. A project with no preset for its language will look clean and prove nothing.

Sonar

SonarQube, or SonarCloud, analyzes source for bugs, vulnerabilities, security hotspots, code smells, duplication, and coverage. The scanner runs in CI and uploads a report. The server applies a quality gate.

  • A vulnerability is a finding Sonar is willing to call unsafe. A security hotspot is a place a human must review, such as a cookie flag or a regex that might be catastrophic. Hotspots do not fail the gate until someone marks them or the gate counts unreviewed hotspots.
  • A useful gate is about new code: no new blocker or critical issues, and coverage on new lines above a threshold. Failing the whole legacy tree on day one teaches people to bypass the gate.
  • Coverage comes from the test report you pass in. A gate of 80 percent with no test report is a gate of zero, and the job should fail for a missing report, not pass as "no data."
  • Sonar and Checkmarx overlap on some injection bugs. Keep both if Checkmarx is the deeper data-flow scan and Sonar is the gate the whole team already watches. Do not treat a Sonar pass as an image scan.

Black Duck

Black Duck is software composition analysis from Synopsys. It identifies open-source components and matches them to known vulnerabilities and licenses.

  • The accurate path is the package manager: pom.xml, package-lock.json, go.sum, requirements.txt, or a Gradle lock. Signature and snippet scans catch copies that are not declared. They also produce more noise.
  • Each component is a name, a version, and the places it was found. A vulnerability is tied to that version. The fix is usually a version bump, then a rebuild, then a rescan. Editing the report does not patch the library.
  • License risk is separate from the CVE. A library can be vulnerability-free and still be a strong copyleft license you are not allowed to ship. Policy should fail the build on both a severity threshold and a forbidden license.
  • The bill of materials from this scan is what the FOSS review reads. If Black Duck cannot see a transitive dependency, the FOSS inventory is incomplete too.

FOSS

A FOSS scan is the open-source compliance pass. FOSS means free and open source software. The question is not only "is there a CVE?" It is "are we allowed to ship this, and what must we do if we do?"

  • Every third-party component needs a license, a version, and a decision: approved, approved with obligations, or rejected.
  • Obligations depend on the license. MIT and Apache want attribution and the license text. LGPL and GPL can require source offers or restrictions on how you link. A proprietary product that statically links GPL code is a legal problem, not a scanner tuning problem.
  • Tools that do this job include Black Duck's license view, FOSSA, and FOSSology. The scan output is an inventory plus notices. Shipping without the notices file fails the obligation even when the security scan is green.
  • A new library is a request, not a drive-by add in a pull request. The scan on main should match the lockfile you released. A dependency added after the FOSS approval is an unscanned component.

Twistlock

Twistlock is the container security product Palo Alto Networks folded into Prisma Cloud Compute. People still say Twistlock for the image scan. It inspects images, registry contents, hosts, and what containers do at runtime.

  • The CI scan runs after the image is built and before it is deployed. The usual CLI is twistcli. The scan is of a digest. Tag latest is not an identity.
  • Findings are OS packages and language packages in the image layers, plus malware and compliance checks such as running as root or a missing health check. A vulnerability in a base image is fixed by rebuilding on a patched base, not by a source change.
  • Set a fail threshold, for example critical and high with a vendor fix available. An unscored finding and a finding with no fix need a documented exception, not a silent pass.
  • Registry scan watches images already pushed, including ones CI did not build. Runtime defenders on the nodes watch process, network, and file behavior. That is a different control from the build gate. A cluster with no defender is not "covered by Twistlock" just because CI scanned the image once.
  • Scan the image you deploy. Scanning a Dockerfile, or an intermediate stage that still contains the compiler, answers a different question.

How to read a red build

  • 2ms red. Rotate the secret first. Then remove it from the tree and from history as far as you can.
  • Checkmarx red. Open the path. If user input reaches the sink, fix the code. If the path is dead, mark it not exploitable and say why.
  • Sonar red. The gate names the condition. New vulnerability: fix it. Coverage drop: add a test. Unreviewed hotspot: review it. Do not raise the leak period to make the gate green.
  • Black Duck red. Upgrade the component. If the fix is not out, confirm the vulnerable code is not reachable, record the exception, and put a date on it.
  • FOSS red. Do not ship. Swap the library, comply with the license, or get an approval. A security waiver does not approve a license.
  • Twistlock red. Rebuild the image on a patched base or an upgraded package. Deploy the new digest. The old digest stays unscanned-as-passed forever.
